## Global executor rules (apply to every plan)

- Any plan that adds or changes Tailwind utility classes in Blade templates must run
  `npm ci && npm run build` and commit the resulting `resources/dist/*.css` changes —
  CI's `assets` job rebuilds from source and fails on any committed-dist mismatch.
  (Learned from plan 017: its "dist out of scope" rule was wrong and broke CI.)

- Verification gates: `composer test` (Pest), `composer lint` (Pint), `composer analyse`
  (PHPStan). All three must exit 0 before each commit.
- Never stage/commit/modify the pre-existing dirty working-tree files:
  `resources/css/docent.css`, `resources/dist/*`, `resources/js/docent-assistant.js`,
  `tests/Browser/assistant.spec.js`, `.design-logo-board.html`,
  `workbench/resources/docs/**/old-*.md`, or this `plans/` directory.
- Never add Co-Authored-By or "Generated with" lines to commit messages.
- Do not push.
- Every plan is behavior-preserving (003 adds tests only): if a test's expected values
  would need to change, STOP and report instead.

## Findings considered and rejected (do not re-audit or "fix" these)

- **Visitor / class-per-node refactor of the AST renderers** (`HtmlRenderer`,
  `AgentMarkdownRenderer`, `MarkdownExporter`, `PlainTextRenderer`,
  `SearchTextRenderer`, `TiptapDocumentParser`, `AstToTiptap`): the `match` dispatch
  tables are long only in arm count; each arm is a readable one-liner. A visitor
  inverts the trade-off against this team's simplicity preference. The real risk
  (silent drops / table divergence) is covered by plan 003's tests instead.
- **`TiptapNodeType` backed enum** for the ~30 wire strings: would be a third copy of a
  contract that also lives in the JS editor extensions; plan 003's round-trip test
  enforces the two PHP tables agree without new ceremony.
- **Theming/branding extraction from `DocentManager`** (`accent`, `logo*`, `favicon`,
  `fontHref`, `themeStyles`, `asset*`): near-trivial config readers; a `ThemeAssets`
  class is over-engineering.
- **`IntegrationRegistry` split**: five parallel kinds with an identical
  register/has/resolve shape — uniform, not mixed responsibilities.
- **`AskController` beyond plan 004 item 2** (e.g. lifting rate-limiting/streaming into
  services): idiomatic controller weight for one "ask" request.
- **`CheckCommand::handle()`**, **`SearchIndexer::sections()`**: length is well-named
  orchestration / a cohesive accumulator; splitting scatters state.
- **Boolean flag params** (`llmsUrl(bool $full)`, `assistantStateNamespace(..., bool $widget)`,
  `AiCorpusBuilder::version(..., bool $widget)`): each toggles a small local detail;
  splitting adds surface for no gain.
- **DTOs for AI citations `{slug,title,url}`, admin tree/group rows, hero/front-matter
  shapes, search heading shape**: all terminate at JSON/Blade/cache/front-matter
  boundaries or stay within one module; VOs would remove no defensive code. The repo
  already has value objects where they earn their keep (`SiteRef`, `Issue`,
  `DocumentSource`, `AiConversation`, `SearchRecord`).
- **`VideoSource::$kind` enum**: never crosses a class boundary.
- **`DocentManager::contextFor` / registration API**: the fluent registration front
  door is pure delegation to `IntegrationRegistry` — it's the manager's job.

### From the 007–012 pre-v1 audit

- **API-08 naming renames** (rename `<docs-component>` → `<docent-component>`; rename
  `docent:insights:prune` → flat form; "fix" the facade `@method` return types): on
  vetting, all three are defensible. `<docs-component>` reads naturally for authors and
  renaming would churn two repos' content fixtures for marginal gain; `docent:insights:prune`
  is legitimate subsystem namespacing (leaves room for `docent:insights:export`); the
  facade docblock already returns `SiteRegistry` accurately (the dual-entry return type is
  inherent, not a bug). Documented as *intentional* in plan 012's COMPATIBILITY.md instead
  of churned. (Reversal of the advisor's initial "do it" call, after reading the code.)
- **API-01b model-rebind contract** (`docent.models` config + container resolution so the
  package itself uses a host subclass): deferred. Plan 010 drops `final` (covers the common
  "extend for my own use" case); a full rebind seam is non-breaking to add later and only
  worth it if users ask.
- **API-03 stringly-typed config** (`authorization.denied_response: "redirect:/login"`,
  `ai.throttle: "10,1"`): accepted as-is. These are conventional-enough Laravel shapes;
  reshaping them into structured arrays is the higher-risk option and the current forms are
  documented as stable. No change.
- **API-10 events beyond the page set** (revisions, AI questions, insight events): out of
  scope for v1. Plan 011 ships the four page events the maintainer approved; the rest are
  non-breaking to add later.
